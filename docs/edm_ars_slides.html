System briefing · for comment

An automated research pipeline, and the reviewer that gates it

EDM-ARS turns a dataset and a research question into a submission-ready manuscript. LSAR reviews it against thresholds calibrated from real published papers. What the two systems do, what they have produced, what they cost — and what went wrong, which is the interesting part.

Chenguang Pan  ·  EDM-ARS v5 / LSAR v0.4  ·  every figure measured from run artifacts

The loop

Dataset in, reviewed manuscript out — unattended

Six agents formulate the question, build the analytic sample, run the estimator, critique their own work, and write the paper. It is then compiled and submitted to an independent reviewer that sees only the PDF.

Architecture — EDM-ARS

Agents propose; deterministic code disposes

A ten-state machine checkpoints after every stage and can resume mid-run. The Critic writes a review, but a deterministic evaluator recomputes the verdict from the issue counts and overrides the model when they disagree.

Architecture4

Architecture — LSAR

An independent reviewer that sees only the PDF

Eight scoring dimensions — relevance, novelty, theoretical grounding, methodological rigor, empirical support, significance, ethics & equity, clarity. Weighted per venue: AERA Open weights rigor 1.4×, reflecting what its reviewers actually penalise.

Why two stages are pinned. Every calibrated threshold was computed from reviews generated and scored by one specific model. Switching either stage invalidates the gate until the anchor papers are re-reviewed — so the code logs a warning and marks the verdict invalid.

Architecture5

The gate

“Good enough” is defined empirically, not chosen

Fetch real published papers from the target venue, review them with the same reviewer, and set the bar at the 25th percentile of what that venue actually publishes. A manuscript passes if it scores like the weaker quartile of the real thing.

The reviewer is noisy — measured test–retest mean absolute difference of 1.9 points. So a borderline score triggers three independent reviews and the gate uses the median. One review cannot decide a paper.

What went wrong

A paper passed its gate at 7.5 with invented numbers

An audit of the first paper routed to a policy journal found it had cleared its bar while containing fabricated results. Handed an empty cell-means table by the analysis stage, the Writer produced a plausible one.

Invented, and present in the submitted manuscript

A full 2×2 table of group means · a follow-wave stability estimate with confidence interval · five pairwise contrast intervals · a methods sentence describing a procedure the code does not perform.

None of these values exists anywhere in the analysis output. The mandatory “unverified” warning that should have accompanied the paper was also missing.

Investigating the reviewer that had waved it through surfaced something worse.

The audit8

Root cause

The reviewer was scoring empty reviews as “Accept”

Four things lined up:

  • The scorer builds its judgement from the review's strengths and weaknesses lists and nothing else.
  • The output template puts strengths before weaknesses.
  • The token limit was set below what the templates ask for.
  • Nothing checked that a review was complete before scoring it.

So a truncated review lost exactly its criticism, and the paper was graded on its praise alone.

21%of all 57 historical reviews were degenerate — no weaknesses at all
+0.83points higher, on average, than complete reviews
7.4score given to a paper whose review file was zero bytes
What it did not do

Recomputing every venue threshold without the defective reviews moves them by at most 0.12 points. Inflated scores sit above a lower-tail threshold and drop out almost without moving it. The published bars were approximately sound; the damage was to individual decisions — and it hit two.

111 of 125 numerals in the manuscript were verified against the analysis output. The 14 that were not are the ones it flagged.

The finding worth arguing about

Telling the model not to fabricate did not work. The prompt-level fix — rendering every missing value as NOT AVAILABLE — do not report a number — changed nothing. It invented the same table anyway.

Only the deterministic checker caught it.

Every defence that failed was an instruction to a model. Every defence that held was code.

The audit10

The response

Five checks between the agents and a published paper

Findings in the shaded checks block a pass outright, independently of the reviewer's score. A venue being uncalibrated cannot override them: “this threshold is untrusted” and “these numbers are untrusted” are different problems.

None of the five asks a model to behave. Each is code that inspects the artifacts and refuses. The suite that pins them grew by 60 tests, including the exact historical failures as regression cases.

Next

What we are working on, and what we are unsure of

Immediate

  • Stop fabrication at source. Detection works; the Writer still invents values when handed empty results, and the analysis stage still produces them.
  • Two venues need recalibrating — their thresholds were set using a review template written for a different venue.
  • Citation uptake. The pipeline assembles 66 usable references and the Writer cites 24.

Longer arc

  • Research taste. Automated idea ranking has been built and measured twice. It correlates with nothing, so it stays advisory and refuses live selection in code until it demonstrably works.
  • Self-improvement. A retrospective agent proposing its own changes against a benchmark, gated by human review.
  • Human evaluation. Blind review of system output against matched human-written papers — the only measurement that settles the question.
